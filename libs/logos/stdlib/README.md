# Standard grammars

Genesis grammars for common languages, each with a mapping file (extensions and editor scopes for the genesis tool) and a
sample file that CTest parses. Import them from your own grammars (`IMPORT General { ... }`, or embed a language with
`IMPORT JSON AS Json { #document }`) by adding this folder to the compiler's search folders (`-I`).

A grammar here follows its specification production by production, and is checked against the official test suite of its
language (`conformance/`, see below). Where a rule of the specification cannot be written as a grammar (a duplicate key, an end
tag that must name its start tag) the grammar does not pretend to enforce it: the test suite files that break such a rule are
listed in `conformance/<language>.semantic`, to be rejected by a semantic analyzer.

| Grammar | Specification | Status |
| --- | --- | --- |
| `JSON.gen` | RFC 8259 / ECMA-404 | complete; passes JSONTestSuite (95/95 accepted, 188/188 rejected) |
| `TOML.gen` | TOML 1.1.0 | complete as a grammar, including the calendar and the Unicode scalar range of escapes; toml-test: all 218 valid files accepted, 439 of 502 invalid ones rejected, the other 63 are key/table definition rules (semantic) |
| `XML.gen` (+ `XMLCharacters.gen`) | XML 1.0, Fifth Edition | every production for a document, DTD internal subset included; W3C xmlconf: all 824 well-formed documents accepted, 784 of 826 not-well-formed ones rejected, the other 42 are well-formedness constraints (semantic). Not provided: the external subset and external parsed entities (separate inputs) |
| `CSV.gen` | RFC 4180 | complete (strict: CRLF, ASCII TEXTDATA); invalid samples are rejected by CTest |
| `CSVRelaxed.gen` | RFC 4180 without its two restrictions on real data | the same rules and token names as `CSV.gen`, but a record ends with CRLF, LF or CR and a field holds any UTF-8 text; used by Ruleforge for dataset snapshots |
| `INI.gen` | none (Windows INI, de facto) | covers sections, `key=value`/`key:value`, `;` and `#` comments |
| `General.gen` | - | a library of templates: lists, dictionaries, Pratt rules, embedding, keywords, and `$_semver` (Semantic Versioning 2.0.0, production by production) |
| `sql/SQLite.gen`, `sql/TransactSQL.gen`, `sql/MySQL.gen` | the ANTLR grammars of grammars-v4, converted | see `sql/README.md`: SQLite 17 of 17 example scripts, T-SQL 110 of 137, MySQL 19 of 24; PostgreSQL and Oracle follow |
| `HTML.gen`, `YAML.gen`, `SQL.gen` | WHATWG HTML, YAML 1.2.2, ISO SQL and its dialects | **not yet to the specification**: tolerant sketches that give an editor structure. YAML needs an indentation facility in the engine, HTML its tokenizer states and SQL one grammar per dialect |

## Conformance

`conformance/fetch.sh DIR` fetches the official suites (toml-test, JSONTestSuite, the W3C XML suite); configure with
`-DLOGOS_CONFORMANCE_SUITES=DIR` and CTest runs `conformance_*`. `conformance/run.py` is the runner: it parses every file of a
suite with the grammar and reports the files the grammar accepts or rejects against the suite's verdict. The XML character
reference patterns are generated by `conformance/charref_regex.py` and verified against every code point.
